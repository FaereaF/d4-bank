| Г2 | API → База Данных | сервисы / хранилище данных | пока никак | Ограничение доступа к БД и разграничение прав |
| Г3 | API → Транспорт | район / шина событий | пока никак | Подпись событий и защита от повторной отправки |

| Г5 | Паспортный стол → API | город / район | пока никак | SSO через OIDC |

## 6. Модель нарушителя

| Внешний злоумышленник | Доступ к шлюзу, инструменты для отправки запросов и анализа API | Получить персональные данные или нарушить работу банка | высокая |

### Реестр угроз
Каждая угроза — отдельная строка. Риск = вероятность (1–5) × ущерб (1–5).
| ID | Элемент DFD | STRIDE | Угроза: кто, что делает, к чему приводит | Вероятность | Ущерб | Риск | Мера (раздел 9) |
|---|---|---|---|---|---|---|---|
| T01 | API района | D | Атакующий отправляет большое количество запросов, из-за чего API перестаёт отвечать | 4 | 4 | 16 | Ограничение частоты запросов, тайм-ауты |
| T02 | База данных | D | Большое количество тяжёлых запросов исчерпывает ресурсы БД и мешает обработке запросов | 3 | 4 | 12 | Ограничение времени запросов и числа соединений |
| T03 | Журналы | D |  Быстрое накопление журналов заполняет диск, из-за чего сервисы перестают работать | 3 | 4 | 12 | Ротация журналов, ограничение объёма и контроль свободного места |
| T04 | API района / База данных | D | База данных становится недоступна, и API не может обрабатывать запросы | 3 | 5 | 15 | Тайм-ауты подключения и проверка доступности БД |
| T05 | Житель → Шлюз → API района | S | Злоумышленник выдаёт себя за другого жителя и отправляет запрос от его имени, из-за чего может получить доступ к чужим банковским данным | 3 | 5 | 15 | Аутентификация пользователей, проверка токенов и принадлежности данных пользователю |
| T06 | Шлюз → API района | T | Злоумышленник изменяет параметры запроса, из-за чего API выполняет операцию с данными, отличающимися от первоначального запроса | 3 | 4 | 12 | TLS, проверка входных данных и целостности запросов |
| T07 | API района | R | Пользователь отрицает выполнение финансовой операции, а отсутствие достаточных журналов не позволяет установить, кто и когда её инициировал | 3 | 4 | 12 | Аудит операций, отметки времени, защита журналов от изменения |
| T08 | API района | I | Злоумышленник запрашивает данные чужого счёта, а API возвращает их без проверки прав доступа | 3 | 5 | 15 | Проверка прав доступа для каждого объекта и запроса |
| T09 | API района / База данных | E | Пользователь с обычными правами вызывает административный метод или использует избыточные права учётной записи приложения, получая доступ к недоступным операциям | 3 | 5 | 15 | Проверка ролей, минимальные привилегии, разделение прав приложения и администратора |
| T010 | База данных | T | Злоумышленник с доступом к учётной записи приложения изменяет записи о счетах, из-за чего данные становятся недостоверными | 2 | 5 | 10 | Ограничение прав записи, проверка операций, резервное копирование |
| T011 | База данных | I | Злоумышленник получает доступ к резервной копии БД и читает персональные и финансовые данные клиентов | 2 | 5 | 10 | Контроль доступа к резервным копиям, шифрование и безопасное хранение |
| T012 | Журналы / SOC | T/R | Злоумышленник изменяет или удаляет записи о действиях, из-за чего расследование инцидента становится неполным и его действия сложнее установить | 3 | 4 | 12 | Ограничение прав на журналы, централизованное хранение и контроль целостности |
| T013 | API → Транспорт | T | Злоумышленник с доступом к транспорту подменяет событие о финансовой операции, из-за чего другой сервис обрабатывает ложные сведения | 2 | 5 | 10 | Проверка источника и целостности событий, аутентификация отправителей |
| T014 | API → Транспорт | I | Злоумышленник получает доступ к сообщениям транспорта и читает содержащиеся в них персональные или финансовые данные | 2 | 4 | 8 | Разграничение доступа к транспорту, минимизация данных в событиях |
| T015 | Паспортный стол → API | S | Злоумышленник отправляет поддельный токен идентификации, а API принимает его и предоставляет доступ от имени другого пользователя | 3 | 5 | 15 | Проверка подписи, срока действия, издателя и аудитории токена |
| T016 | Репозиторий Git / конфигурация API | I | Разработчик случайно публикует пароль или ключ доступа в репозитории, после чего злоумышленник использует секрет для подключения к внутренним сервисам | 2 | 5 | 10 | Не хранить секреты в Git, использовать переменные окружения или хранилище секретов, менять опубликованные ключи |

## 10. Остаточные риски
T10 (изменение записей в базе данных) — полностью не закрываем: администратор БД с достаточными привилегиями технически может изменить банковские данные. Снижаем риск ограничением прав доступа, резервным копированием и журналированием операций с базой данных

T01 (массовые запросы к API) — закрываем частично: используем ограничение частоты запросов и тайм-ауты. Полноценная защита от масштабной распределённой атаки на шлюз находится за пределами ответственности района

Любопытный администратор района — полностью не закрываем: администратор с достаточными техническими привилегиями может прочитать данные в базе. Снижаем риск журналированием доступа администратора и проверкой журналов (планируется на неделе 7)
